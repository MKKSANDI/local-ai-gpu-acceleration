# Architecture

The runtime is built around a strict residency rule: large tensors should enter VRAM once, remain under explicit ownership, and avoid host traffic during steady-state decode.

## Control Plane

The CPU side owns:

- request normalization and admission;
- tokenization while GPU tokenization is still research;
- pinned host staging at request boundaries;
- telemetry aggregation;
- profile/trace orchestration;
- policy selection: strict, balanced, overflow.

The CPU side must not download logits or large tensors during generation.

## GPU Data Plane

The GPU side owns:

- immutable weight arena;
- page-based KV arena;
- graph workspace arena;
- DMA/staging arena;
- fused kernels;
- decode graph replay;
- sampling whenever practical.

## Module Contract

`allocator` reserves and partitions VRAM. Runtime CUDA allocation during decode is a bug.

The allocation policy is stress-tested first in `tools/bench/allocator_sim.py`: immutable weights are allocated once, KV/workspace/DMA arenas are separate, transient allocations must reuse fixed arena space, and overflow is counted as rejection rather than hidden expansion.

`scheduler` predicts resident weight, predicted/current KV, workspace, workspace high-water, DMA, graph, and WDDM-guard pressure before work is admitted. Strict rejection reports the same memory breakdown plus over-budget bytes instead of collapsing everything into a single opaque allocation number. `runtime/core/scheduler/layer_plan.*` owns the reusable layer role/phase contract: role ranking, role-to-phase classification, contiguous phase segmentation, unknown-role counting, strict phase-order validation for executor admission, and a phase execution plan that maps validated segments to per-phase matvec, activation-feedback, and total graph-kernel counts. `runtime/core/scheduler/layer_executor.h` replays that validated execution plan through named attention, FFN, SSM, and output phase callbacks, derives phase-local workspace descriptors from the same stage envelope, converts those descriptors into aligned phase-local activation/logits allocations, builds named auxiliary descriptors for FFN branch caches, SSM recurrent state, SSM scan/selective scratch, and generic per-phase scratch descriptors for future attention/SSM kernels, binds the allocation plan to reusable runtime pointers, builds explicit phase-local activation-feedback edges, and computes logical high-water usage for those slices. Graph capture, warmup, phase timing, workspace reporting, feedback-edge routing, and concrete workspace slices therefore share one executor contract before the callbacks become real phase math. `runtime_layer_plan_selftest.exe` gates this contract with native fixtures for the accepted role plan, chained/unchained execution counts, phase-local workspace descriptors, phase-local activation/logits allocation, auxiliary, SSM recurrent-state, SSM scan-scratch, and phase-scratch allocation, runtime binding, phase-local feedback dataflow, workspace high-water usage, strict admission breakdowns, graph-bucket admission estimates, over-budget rejection, executor full/phase replay, named phase dispatch, executor bounds rejection, and failure cases for empty plans, empty workspaces, unknown roles, unknown phases, bad phase order, segment-count mismatch, and empty segments.

`kv` stores sequence state in fixed-size pages and exposes logical indirection rather than moving hot pages.

The page lifecycle is tested first in `tools/bench/kv_cache_sim.py`: prefix pages are shared by refcount, active sequences own private generation pages, and pressure is handled by rejection plus prefix reclaim instead of silent spill.

`graphs` captures and replays a bounded set of decode/prefill buckets. `runtime/core/graphs/cuda_graph_bucket.h` now owns both the CUDA Graph RAII wrapper and a graph-bucket admission estimate: bucket name, batch/query bucket, phase count, kernel launches, workspace high-water, metadata bytes, workspace guard bytes, and total bytes. Mixed layer rows feed that estimate into strict admission as `admission_graph_bytes` before CUDA graph capture, so graph residency is budgeted instead of only measured after the fact.

`kernels` holds fused CUDA implementations. Early kernels are synthetic until loader and tensor layouts are stable.

The first LLM-shaped native primitive is `rtxllm_launch_q4_matvec_decode`: it reads packed Q4 weights, dequantizes inside the matvec loop, writes logits, updates a page-style KV arena, and updates the token on GPU before only the token ID is copied back. The default `packed2` variant consumes one packed byte per loop iteration and dequants both nibbles from that load. The `packed2_vec4x4` variant uses four warps per output row with aligned `uint32_t` packed-Q4 loads, aligned `float4` activation loads, and shared row-partial reduction, giving the raw packed-payload ceiling a comparable row-parallel shape to the best Q4_K path.

`telemetry` emits machine-readable benchmark records and enough event timing to guide Nsight captures.

`gguf_tensor_plan.py` is the loader-facing planning bridge: it reads local GGUF metadata, derives tensor spans from tensor offsets, groups `blk.N.*` tensors into layers, and estimates how many complete layers fit in the current strict VRAM budget.

## First Engineering Milestone

The current milestone is not full model inference. It is a measurable resident execution path:

1. allocate large GPU-resident buffers;
2. reserve a simulated KV page arena;
3. run repeated decode-like kernels;
4. copy back only token-sized data;
5. emit latency, transfer, and residency metrics.

That gives a baseline for launch overhead and Windows/WDDM stability while the native compiler path and GGUF loader mature.

The current native path includes both launch-per-step and CUDA Graph baselines plus `runtime_fused_bench.exe`, which captures the packed Q4 matvec decode step into a graph and replays it without steady-state H2D traffic.

`runtime_fused_bench.exe --check-only` is the correctness gate for this primitive. It runs the CUDA Q4 matvec path on a small deterministic shape, computes a CPU reference for logits, KV writes, and token selection, and emits pass/fail plus maximum absolute errors.

Allocator resets now support both conservative synchronous reset and stream-ordered reset. The native benchmark apps use `VramSuperallocator::reset_async(stream)` on the same non-blocking stream as their subsequent uploads, warmups, graph capture, and decode launches. This preserves the ordering fix that stopped default-stream reset races without forcing a global `cudaDeviceSynchronize()` into the hot setup path.

`runtime_gguf_probe.exe` is now the native loader gate for the target GGUF. It validates all tensor spans, reads the first real `Q4_K` block from `blk.0.attn_qkv.weight`, decodes the block's FP16 scale/min metadata on CPU, and dumps both the packed payload and the full 144-byte GGML Q4_K block stream.

`runtime_fused_bench.exe` has two target-weight modes. `--weights-file` consumes the packed payload with synthetic per-row scales for a raw packed-byte ceiling; `--packed-kernel block|vec4x4` selects the default one-block-per-row path or the four-warp row-split packed ceiling. `--q4k-blocks-file` consumes full Q4_K blocks and decodes the real scale/min metadata on GPU, which is slower but materially closer to the loader/kernel path the runtime needs. The full-block path now shares the CPU reference gate, comparing logits, KV writes, and token selection against host-side Q4_K dequantization. `--q4k-kernel shared` caches the eight scale/min pairs for each Q4_K block in shared memory before processing the 128 packed bytes. `--q4k-kernel warp` assigns one warp per row and uses warp shuffle reduction to reduce block-wide synchronization. `--q4k-kernel broadcast` keeps the warp-per-row shape but only lanes 0-7 decode scale/min pairs, then broadcasts them with warp shuffle instructions. `--q4k-kernel vec4` keeps that broadcast metadata path and changes each lane to consume one aligned 32-bit packed Q4 load plus two aligned `float4` activation loads. `--q4k-kernel vec4x2` uses two warps per output row, splitting Q4_K blocks across the warps and reducing their row partials in shared memory. `--q4k-kernel vec4x4` extends the same row-split design to four warps per row. `--q4k-kernel predecoded` keeps the full Q4_K block payload but uploads a predecoded scale/min table at setup, isolating the in-kernel metadata decode cost from the remaining full-block payload stride cost. `--q4k-kernel split-predecoded` combines that metadata side table with the staged 128-byte-per-block payload stream, modeling the runtime's internal packed layout rather than the original 144-byte GGML block stride. `--q4k-kernel split-half` keeps the staged payload stream but stores the predecoded `(scale, min)` side table as FP16 half pairs, cutting metadata residency in half at the cost of a small, explicit lossy-reference tolerance and extra half conversion on the hot path. `--q4k-kernel split-compact` and `--q4k-kernel split-native` are exact compact metadata experiments: `compact-u8` stores FP16 `d/dmin` plus unpacked scale/min bytes in 20 bytes per block, while `native16` stores the original 16 metadata bytes separately from the aligned payload. Both prove that compact exact metadata saves residency, but still leaves hot-path scale/min reconstruction as the bottleneck.

`q4k_resident_pack.py` is the first offline internal-layout packer. It reads Q4_K tensor bytes directly from GGUF tensor offsets, writes one payload file plus one metadata file per tensor, and records checksums, dimensions, source offsets, metadata format, resident bytes, and the matching `runtime_fused_bench.exe --q4k-kernel` policy in `manifest.json`. The current `auto` policy is deliberately shape-aware: large QKV tensors keep FP32 predecoded product metadata for speed, while small V tensors use exact compact metadata for lower residency.

`iq_resident_pack.py` is the first IQ-family loader bridge. It copies verified raw IQ block streams from the GGUF into external-storage resident payload files and records type, dimensions, block count, source offset, checksums, and runtime-kernel labels. `runtime_iq_probe.exe` validates that boundary by loading `IQ2_S` or `IQ3_S` manifest tensors, uploading raw GGML blocks into the superallocator, replaying a CUDA Graph over a resident block-reader kernel, and comparing GPU-observed byte/field checksums against a CPU reference. IQ2_S validates the 82-byte block layout; IQ3_S validates the 110-byte block layout including `qs`, `qh`, `signs`, and scale nibbles. `runtime_iq_matvec_probe.exe` uses upstream GGML IQ2_S k-grid semantics and upstream IQ3_S `iq3s_grid` semantics to dequantize resident IQ-family blocks inside CUDA matvecs, write page-style KV entries, update the token on GPU, and copy back only a token-sized value during graph replay. Its post-run CPU reference checks logits, KV, and final token. `runtime_iq_sequence_bench.exe` promotes the IQ2_S path into a manifest-driven sequence: selected IQ2_S tensors are source-plan validated, uploaded into one resident weights arena, launched from one captured graph, optionally chained through GPU activation feedback, and reported with role counts.

`q5k_resident_pack.py` closes the remaining target source-loader gap at the raw-block level. It copies the single `Q5_K` `output.weight` tensor into an external-storage resident payload file, records the source offset, dimensions, block count, checksums, and raw-block runtime label, and writes a manifest under `E:\AI project\packs\q5k`. `runtime_q5k_probe.exe` consumes that manifest, uploads the full `349634560` byte resident payload into the superallocator, replays a CUDA Graph over a resident block-reader kernel, and checks the full payload checksum plus first-block Q5_K `d`, `dmin`, scale, high-bit, and low-bit fields against CPU reference values. `runtime_q5k_matvec_probe.exe` now dequantizes that resident Q5_K payload in a decode-style CUDA matvec, writes page-style KV entries, updates the token on GPU, and copies back only a token-sized value during graph replay. Its CPU reference mirrors GGML's Q5_K scale/min and high-bit layout, so Q5_K now has both raw loader residency and CUDA dequant validation.

`runtime_fused_bench.exe --q4k-manifest <manifest.json> --q4k-tensor <name>` is now the native manifest-consumption boundary. It resolves the selected tensor, validates payload and metadata checksums, uploads the payload plus metadata file directly into the weight/workspace arenas, and dispatches the manifest's runtime kernel policy. If the manifest also contains a `blocks_path`, `--check-only` keeps using the full source blocks for the CPU reference gate. Full packs omit blocks and run from resident payload plus metadata only.

`runtime_q4k_sequence_bench.exe` is the first multi-tensor native resident path. It selects one or more Q4_K manifest tensors, validates their dimensions/type/source span against the source GGUF tensor plan when available, admits their combined payload and metadata residency as one strict request, uploads every selected tensor into a shared weights arena plus metadata arena, and captures the whole tensor sequence into one CUDA Graph. The default mode inserts a GPU activation-feedback kernel after every tensor matvec, turning each tensor's logits into the next tensor's activation buffer before the graph advances. This is still not a transformer layer executor, but it exercises the next runtime invariant: many packed tensors resident together, one allocation plan, source-plan shape validation, graph-captured inter-stage data dependency, no steady-state H2D traffic, one token-sized D2H copy per graph replay, and measurable graph replay latency for a fixed tensor sequence.

`runtime_mixed_sequence_bench.exe` is the first mixed-format native resident path. It selects Q4_K plus IQ-family tensors for a layer, accepts additional IQ manifests with `--extra-iq-manifest`, can optionally append a Q5_K `output.weight` stage, validates all selected manifest families against the same source GGUF tensor plan, admits the combined Q4_K payload/metadata plus IQ2_S/IQ3_S/Q5_K raw payload residency as one strict request, uploads each format into resident arenas inside one superallocator plan, and captures one CUDA Graph containing Q4_K, IQ2_S, IQ3_S, and optional Q5_K decode-style matvec kernels. Stage ordering defaults to source-plan-derived layer-local tensor offsets with global tensors such as `output.weight` kept at the tail; `--stage-order role-plan` instead uses the core layer-plan role order (`attn_gate`, `attn_qkv`, FFN gate/up/down, SSM, then global output) and emits `stage_role_plan_unknown_roles` so unknown roles cannot hide in the execution plan. The runner adapts its local stage list into `rtxllm::LayerStageDescriptor` and delegates phase classification, phase counts, contiguous phase segments, strict validation, graph-work accounting, phase-local workspace descriptor construction, aligned activation/logits allocation, named auxiliary workspace allocation, SSM recurrent-state and scan-scratch allocation from `--ssm-phase-mode recurrent-state|scan-scratch|selective-scan|source-parameterized|source-parameterized-fused`, generic per-phase scratch allocation from `--phase-scratch NAME:PHASE:VALUES`, runtime binding, activation-feedback edge construction, and workspace high-water accounting to `runtime/core/scheduler/layer_plan.*` plus `runtime/core/scheduler/layer_executor.h`, giving the next layer executor a shared admission, phase-execution, workspace-allocation, workspace-binding, dataflow-routing, and workspace-pressure contract instead of benchmark-local rules. The runner also builds a core CUDA graph bucket plan from the actual per-graph kernel count and layer workspace high-water, emits per-bucket metadata/workspace guard bytes, and charges the total as `admission_graph_bytes`; `--graph-bucket-count`, `--graph-batch-bucket`, and `--graph-query-bucket` let the harness model more than one captured decode bucket. When attention QKV scratch mode is enabled, the runner allocates the core-owned `attention_qkv_state` slice, launches `rtxllm_launch_attention_qkv_scratch` after the attention phase callback, writes Q/K/V-style scratch values, and feeds a deterministic attention residual into the FFN activation through the same CPU reference path. When attention QKV reduce mode is enabled, it keeps that scratch writer and then launches `rtxllm_launch_attention_qkv_reduce` to consume Q/K/V scratch rows and apply a bounded weighted residual to the FFN activation before the FFN phase consumes it. When attention QKV window mode is enabled, it keeps the scratch writer and then launches `rtxllm_launch_attention_qkv_window` to compute a small stable softmax over Q/K scratch rows, aggregate V scratch rows, and apply the context residual to the FFN activation. When attention QKV head-window mode is enabled, it keeps the same scratch writer and launches `rtxllm_launch_attention_qkv_head_window`, which interprets Q/K/V scratch as contiguous per-head row blocks, computes a local stable softmax window inside the selected head, and aggregates V rows without crossing head blocks. When attention QKV head-dim, head-tile, or head-group mode is enabled, the runner keeps the same scratch writer and second attention kernel envelope while using explicit head/context/head-dim scratch addressing, first with per-lane dot products, then with one score window per head/context tile, then with grouped query-context blocks that reduce small-tile launch overhead. When phase scratch descriptors are present, the runner launches `rtxllm_launch_phase_scratch_digest` after the matching attention/FFN/SSM/output phase callback, so generic scratch slices are touched inside warmup, CUDA Graph capture/replay, and per-phase timing rather than only being reserved. When SSM recurrent state is enabled, the runner launches `rtxllm_launch_ssm_recurrent_state` after the SSM phase, mutates the core-owned `ssm_recurrent_state` slice, and feeds the output activation through the same CPU reference path. When SSM scan-scratch mode is enabled, the runner reserves both `ssm_recurrent_state` and `ssm_scan_scratch`, launches `rtxllm_launch_ssm_scan_scratch` after the SSM phase, updates scan scratch plus recurrent state, and feeds output activation through the same CPU reference path. When output final-token mode is enabled, the runner launches `rtxllm_launch_output_token_sample` after the output phase callback, keeps sampling on GPU from the output logits, and reports `output_phase_kernel_launches_per_graph` beside the core graph-work count. `--strict-layer-plan` turns that contract into an admission gate: it requires role-plan ordering, known roles, known phases, and contiguous `attention -> ffn -> ssm -> output` phase segments before graph setup proceeds. The emitted `layer_execution_phases` array names the per-phase kernel envelope and timing samples; `layer_executor_phase_workspaces` names the matching per-phase row/column/logical-value envelope, activation/logits offsets, high-water bytes, and slack bytes; `layer_executor_aux_workspaces` names core-owned auxiliary buffers such as `ffn_gate_cache`, `ffn_up_cache`, `attention_qkv_state`, `ssm_recurrent_state`, `ssm_scan_scratch`, `attention_qkv_scratch`, and `ssm_state_scratch`; `layer_executor_activation_feedback_plan` names the source stage, target stage, source/target phase, row/column envelope, phase-crossing flag, and wrap flag for every feedback edge. The default `feedback_mode` is `rmsnorm`, which replaces the previous synthetic squashing handoff with a CUDA RMSNorm-style normalization of source logits into the target activation buffer; `--feedback-mode synthetic` remains available for comparison, and `--feedback-mode phase-aware-ffn-silu` keeps RMSNorm outside FFN while using a CUDA SiLU-on-normalized-logits handoff for FFN-internal dataflow edges. `--feedback-mode phase-aware-ffn-gated-silu` uses a core auxiliary FFN gate cache: the gate shared-expert output is RMS-normalized and cached through SiLU, then the up shared-expert output is RMS-normalized and multiplied by that cached gate before entering the down projection. The newer `--ffn-phase-mode gated-silu` path is the first phase-local gated FFN primitive: gate and up expert/shared-expert stages keep the same FFN input activation, cache normalized `SiLU(gate)` and normalized `up` branch values into separate core auxiliary workspace slices, and write `SiLU(gate) * up` as the down-projection activation with one product edge. The newer `--attention-phase-mode qkv-scratch` path is the first attention-local phase primitive: it reserves attention QKV scratch, adds one captured attention kernel, and applies the attention residual before FFN stages consume their activation. The newer `--attention-phase-mode qkv-reduce` path adds a second captured attention kernel that consumes the Q/K/V scratch and applies a bounded weighted residual. The newer `--attention-phase-mode qkv-window` path replaces that residual with a small softmax-window context over Q/K/V scratch, moving the primitive closer to real attention dataflow while keeping the same residency and CPU reference contract. The newer `--attention-phase-mode qkv-head-window` path keeps the two-kernel contract but makes the window head-local, so the benchmark now exercises a per-head/block Q/K/V addressing pattern before FFN consumption. The newer `--ssm-phase-mode recurrent-state` path keeps a persistent phase-local recurrent state slice, combines previous state, SSM logits, and the output activation in a captured CUDA kernel, and reports the added SSM kernel and workspace bytes in admission telemetry. The newer `--ssm-phase-mode scan-scratch` path extends that contract with a core-owned scan scratch slice and a captured scan kernel that updates scan scratch, recurrent state, and output activation together. The newer `--ssm-phase-mode source-parameterized` path reuses that scan scratch slice as alpha/beta parameter cache, adds two captured source-parameter cache kernels before the final SSM update, and then updates scan scratch, recurrent state, and output activation from source-derived parameters. The `--ssm-phase-mode source-parameterized-fused` comparison folds those cache writes into RMSNorm feedback with `rtxllm_launch_ssm_rmsnorm_feedback_parameter_cache`, preserving the scan-scratch graph-byte envelope. The newer `--output-phase-mode final-token` path is the first output phase primitive: it samples the final token from output logits inside captured graph replay and copies only token-sized data back to CPU. The runner also snapshots CUDA free memory around graph capture, instantiate, upload, and destroy so graph pressure is visible beside workspace pressure. Admission telemetry now reports resident weights, predicted and allocated KV, phase workspace, auxiliary workspace, attention QKV scratch workspace, SSM recurrent workspace, SSM scan/source-parameter scratch workspace, generic scratch workspace, total workspace allocation and high-water, workspace slack, DMA, graph bucket bytes, WDDM guard, usable bytes, required bytes, and over-budget bytes from the same request estimate used by strict admission. Phase timing is measured by a post-graph CUDA-event phase replay so the primary graph wall-time metrics remain pure captured-graph replay measurements. With `--check-reference`, the runner now resets graph state, executes the same staged path outside the timed graph, snapshots per-stage logits/token values before activation feedback, computes the CPU matvec/page-KV/token/activation-feedback/attention-QKV/attention-QKV-reduce/attention-QKV-window/attention-QKV-head-window/attention-QKV-head-dim/attention-QKV-head-tile/attention-QKV-head-group/SSM-recurrence/SSM-scan/SSM-source-parameterized/output-token path through the same feedback edge plan, feedback mode, FFN phase mode, attention phase mode, SSM phase mode, and output phase mode, and emits both a hard final `reference_passed` gate and per-stage `reference_stage_results`. The current output slices cover all `8` IQ2_S tensors, the two IQ3_S down-projection tensors, one Q4_K `attn_qkv` tensor, and global `output.weight` for both layer 0 and layer 1. This is not yet a complete transformer-layer executor, but it proves the loader, residency, graph-capture, KV/token, graph-bucket admission, GPU-side attention/SSM/output primitives, and runtime-bound phase-local device-side activation contracts across four quant families on more than one model layer.
